# Phase 2 — LLM-Based Plan Generation & Weekly Synthesis
## Sub-Phase ID: Phase-2.4

## Objective
Replace the deterministic Python plan generation with LLM-driven generation. The `PlanGenerationAgent` produces a single strategic framework (simplified from the three-hypothesis approach) that gets persisted as the TrainingPlan. This ensures the plan is personalized to the athlete's actual state from day one using LLM reasoning.

## Challenge Notes
Phase 1.4 used a pure Python service (`PlanGenerationService`) that generated plans from templates. Phase 2.4 replaces this with LLM-driven generation:

**Simplification:** Instead of `HypothesisAgent` + `HypothesisSelector` (three hypotheses with scoring), this phase uses a single `PlanGenerationAgent` that produces one strategic framework. This deferral keeps the hypothesis selection complexity for a later phase while still enabling LLM-based personalization.

**Benefits of this simplification:**
- Reduced complexity in the generation pipeline
- Still gets LLM personalization based on athlete twin state
- Can add multi-hypothesis exploration later without breaking the model
- Single failure point is easier to manage

## Capabilities Delivered
- `PlanGenerationAgent` produces strategic framework from athlete context
- Phase definitions generated by LLM (not hardcoded templates)
- Weekly distributions produced by LLM (session count, intensity targets)
- Session-level intent descriptions in natural language
- Week 1 `WeeklyPlan` created atomically with the TrainingPlan
- `PreWeekReviewAgent` evaluates weekly readiness for ongoing weeks
- `WeeklySynthesisAgent` produces sessions for weeks 2+
- Checkpoints scheduled based on confidence gaps and phase positions
- Template fallback when LLM fails

## Invariants To Preserve
- Hard constraints enforced regardless of generation method
- No two consecutive quality sessions in generated schedule
- Long run always followed by rest/recovery
- Distribution sums ≤ 1.0 per phase
- Specificity values 0.0–1.0
- Phase objectives use valid ObjectiveCategory values
- Session count respects athlete's weekly availability
- Confidence level determines plan conservatism (LOW = wider buffers)

## Exit Gate
- After onboarding, `PlanGenerationAgent` produces a `StrategicFramework`.
- `TrainingPlan` exists with phase_definitions appropriate to goal type.
- `WeeklyPlan` for Week 1 exists with appropriate session count and types.
- Checkpoints scheduled based on confidence gaps and race calendar.
- No back-to-back quality sessions in generated schedule.
- Sessions only appear on athlete's available days.
- When LLM fails, template fallback produces a valid plan respecting constraints.
