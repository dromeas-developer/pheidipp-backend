# Pheidipp — Product Vision

## What Is Pheidipp
Pheidipp is an AI-powered running coach.
Named after Pheidippides, the ancientGreek messenger who ran from Marathon to Athens, it is a science-backed platform that acts as a personal coach for endurance runners — understanding their physiology, tracking their training load, and generating personalised plans.

The system is a backend API, background worker, and web frontend that:
- Ingests FIT files from GPS running watches via direct upload or Garmin/COROS sync
- Computes training load metrics (CTL, ATL, TSB) from the full activity history
- Maintains a per-athlete physiological model (thresholds, zones, calibration state)
- Maintains a Digital Twin — a living simulation of the athlete's physiology that can forecast fitness, predict race times, and model training block outcomes
- Generates AI-coached training plans and individual workouts via a multi-agent LLM pipeline
- Analyses completed workouts for execution quality and trend detection

---

## Core Principles

**Running only** — the platform is purpose-built for running. All agents refuse off-topic requests. No general-purpose chatbot behaviour.

**Privacy first** — no raw PII ever reaches an LLM API. All prompts are scrubbed by a PromptSanitiser before dispatch.

**Science-backed** — zone frameworks, threshold models, and calibration methods are grounded in published exercise physiology research. Primary references:
- Seiler (polarised training)
- Friel (Training Bible)
- Daniels (Running Formula)
- Vance and 80/20 Running (intensity distribution).

## Core Data Model (Conceptual)

Understanding these relationships guides implementation decisions — especially
what must be stored vs what can be computed, and what the Digital Twin depends on.

```
Athlete
  ├── Activities              — FIT file ingestion, raw workout data
  │     └── ActivitySamples   — per-second time-series (heart rate, power, pace)
  │
  ├── AthleteWellness         — daily: sleep, HRV, resting HR, weight
  ├── AthletePhysiology       — versioned: FTP, LT1, LT2, VO2max, max HR
  │     (effective_from / effective_to date ranges)
  │
  ├── AthleteFitness          — daily: ATL, CTL, TSB, total_tss
  │     (computed from activity history by worker jobs)
  │
  └── DigitalTwin             — physiological simulation layer
        ├── reads AthletePhysiology (current thresholds)
        ├── reads AthleteFitness (training load history)
        ├── forecasts: fitness trajectory, race time prediction
        └── drives: TrainingPlan generation

TrainingPlan
  ├── generated by LLM agents using DigitalTwin state
  ├── broken into Workouts (individual sessions with targets)
  └── adapts based on completed activity analysis
```

## Why Stored History Matters

Several architectural decisions follow from the Digital Twin requirement:
- **ATL, CTL, TSB must be stored** — the Digital Twin models "what if I add a 20km long run?" which requires querying historical load, not recomputing it
- **Physiology must be versioned** — training zones change over time; historical activities must reference the physiology valid at the time of the workout
- **Wellness is time-series** — HRV trends over weeks drive recovery recommendations; spot values are insufficient
- **ActivitySamples are hypertables** — per-second data for a year of training is millions of rows; TimescaleDB partitioning is non-negotiable

## Implementation Phases

### Phase 1 — Foundation (Current)
- Athlete profile and authentication
- Activity ingestion (FIT file upload)
- Historical metrics storage (wellness, physiology, fitness)
- Basic training load computation (ATL, CTL, TSB via worker jobs)

### Phase 2 — Intelligence
- Digital Twin implementation
- AI coaching agents (plan generation, workout builder)
- Garmin/COROS API sync
- Workout execution analysis

### Phase 3 — Social & Professional
- Group training plans (friends sharing one plan, individual zones)
- Race prediction and performance forecasting

## What Does Not Belong Here
- Generic chatbot or assistant behaviour
- Any feature not grounded in exercise physiology research
